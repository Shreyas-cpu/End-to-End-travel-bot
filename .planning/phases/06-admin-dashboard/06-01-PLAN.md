<objective>
Build an Admin Dashboard allowing the developer to insert API keys (Booking.com, Amadeus, LLMs), toggle Mock vs Live modes, inspect bookings, and manage RAG documents without redeploying.

Purpose: Provide an operational control plane for partner API key provisioning and platform monitoring.
Output: configService, admin REST endpoints, and single-page Admin Dashboard interface.
</objective>

<tasks>
<task type="create">
  <files>src/services/configService.ts</files>
  <action>
    Build ConfigService:
    - Manages `data/runtime-config.json` (merging with `.env` defaults).
    - Stores API keys: `bookingComApiKey`, `bookingComAffiliateId`, `bookingComPaymentApiKey`, `bookingComMerchantId`, `amadeusApiKey`, `amadeusApiSecret`, `llmProvider`, `geminiApiKey`, `openAiApiKey`.
    - Stores provider modes: `hotelProvider` (mock/booking_com), `flightProvider` (mock/amadeus), `cabProvider` (mock/uber), `llmProvider` (gemini/rule_engine).

  </action>
  <verify>npx tsc --noEmit</verify>
</task>

<task type="create">
  <files>src/routes/adminRoutes.ts</files>
  <action>
    Implement Express router `/api/admin`:
    - `POST /login`: Verify admin token/credentials.
    - `GET /config` & `POST /config`: Read/update runtime configuration.
    - `GET /bookings`: List all bookings with customer details, amounts, and PDF links.
    - `GET /sessions`: List active chat sessions and message logs.
    - `GET /health`: Detailed server diagnostics, uptime, and latency.
    - `GET /knowledge` & `POST /knowledge`: List and edit RAG knowledge files.
  </action>
  <verify>npx tsc --noEmit</verify>
</task>
